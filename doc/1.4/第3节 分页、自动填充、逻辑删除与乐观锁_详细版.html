二、核心知识点

8.3.1 插件链：MybatisPlusInterceptor

MP 3.5.x 的插件统一装进 MybatisPlusInterceptor，再往里 add 一个个 InnerInterceptor。本项目注册了两个：分页（必加，否则 selectPage 不生效）与乐观锁；分页还设置了 setMaxLimit(500) 防止一次拉取过多。

java
public class MybatisPlusConfig {

    public static MybatisPlusInterceptor buildInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

        PaginationInnerInterceptor pagination =
                new PaginationInnerInterceptor(DbType.MYSQL);
        pagination.setMaxLimit(500L);              // 单页上限 500 条
        interceptor.addInnerInterceptor(pagination);

        interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());

        return interceptor;
    }
}

8.3.2 物理分页：Page

Page<T> 携带页码与页大小，查询后 IPage 回填 total / pages / records。分页插件自动拼 LIMIT 并追加一条 SELECT COUNT(*)。

java
Page<Student> page = new Page<>(2, 3);          // 第 2 页，每页 3 条

LambdaQueryWrapper<Student> wrapper = new LambdaQueryWrapper<>();
wrapper.orderByDesc(Student::getScore);

IPage<Student> result = studentMapper.selectPage(page, wrapper);

result.getTotal();      // 总记录数
result.getPages();      // 总页数
result.getCurrent();    // 当前页码
result.getSize();       // 每页条数
result.getRecords();    // 当前页数据

8.3.3 自动填充：MetaObjectHandler

实体上 @TableField(fill = FieldFill.INSERT / INSERT_UPDATE) 标记填充字段，处理器里用 strictInsertFill（字段为 null 才填，不覆盖手动值）或 setFieldValByName（强制覆盖）。注意：MetaObjectHandler 不属于 InnerInterceptor，要挂在 GlobalConfig 上。

java
public class MyMetaObjectHandler implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        LocalDateTime now = LocalDateTime.now();
        // 严格填充：只有字段为 null 时才填充，不覆盖手动设置的值
        this.strictInsertFill(metaObject, "createTime", LocalDateTime.class, now);
        this.strictInsertFill(metaObject, "updateTime", LocalDateTime.class, now);
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        // INSERT_UPDATE 类型的字段，在 UPDATE 时也会走这里
        this.strictUpdateFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }
}

// 注册（StudentTest.init() 中）：
GlobalConfig globalConfig = new GlobalConfig();
globalConfig.setMetaObjectHandler(new MyMetaObjectHandler());
GlobalConfigUtils.setGlobalConfig(configuration, globalConfig);

8.3.4 逻辑删除：@TableLogic

加 @TableLogic 后，MP 对该实体的删除全部改写为 UPDATE，查询自动追加 WHERE deleted=0。物理删除该用什么时候？——需要真删时用自定义 SQL 或去掉注解。

java
// 执行 deleteById(12) 时，MP 实际执行的 SQL：
// UPDATE mp_student SET deleted=1 WHERE id=12 AND deleted=0

studentMapper.deleteById(tmpId);
Student gone = studentMapper.selectById(tmpId);   // null：查询自动过滤 deleted=1

// selectCount 等所有内置方法同样自动过滤，无需手写条件

8.3.5 乐观锁：@Version

更新时 MP 自动追加 WHERE version = 旧值 并 SET version = 旧值+1。若数据已被别人改过（version 不匹配），影响行数为 0——更新被安全丢弃，适合低冲突的并发写场景。

java
Student student = studentMapper.selectById(3L);
student.setScore(66.0);
studentMapper.updateById(student);
// 实际 SQL：UPDATE mp_student SET score=?, version=1 WHERE id=3 AND version=0

// 用「过期版本」更新：
Student stale = new Student();
stale.setId(3L);
stale.setVersion(0);                // 数据库已经是 1，匹配不到
int rows = studentMapper.updateById(stale);
// rows = 0：WHERE version=0 匹配不到，更新被丢弃

六、注意事项与常见坑

⚠️ 分页不生效的最常见原因
  • 没有注册 PaginationInnerInterceptor，或注册时没指定 DbType.MYSQL。
  • 插件注册发生在 MybatisSqlSessionFactoryBuilder.build() 之前——顺序错了等于没注册。
📌 MetaObjectHandler 的注册位置
  • 它不是 InnerInterceptor，别往 addInterceptor() 里塞。
  • 本项目通过 GlobalConfigUtils.setGlobalConfig(configuration, globalConfig) 注册；Spring Boot 集成时交给容器即可自动生效。
✅ 乐观锁失败后的业务处理
  • rows == 0 说明并发冲突，通常的做法是重试（重新读取最新 version 再更新）或提示用户。
  • 乐观锁适合读多写少；高冲突场景应考虑悲观锁或分布式锁。
